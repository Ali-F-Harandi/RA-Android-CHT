1. What is a .cht file?

A .cht file is a plain-text file that RetroArch uses to store cheat codes for a specific game. Each file contains one or more cheat entries that can modify the game's memory in real-time — giving you infinite health, infinite lives, level select, and more.

Cheat files are loaded by RetroArch's built-in Cheat Manager. Once loaded, you can toggle individual cheats on or off from the in-game menu.

Key points:
  • Files are plain text — you can open them in any text editor
  • One file per game, named after the game's ROM hash or a descriptive name
  • Format is INI-style: key = value pairs
  • Each cheat has a numbered prefix (cheat0_, cheat1_, cheat2_...)
  • Values can be decimal numbers, strings, or booleans (true/false)

2. The .cht File Format

Here's the basic structure of a .cht file:

# This is a comment. Lines starting with # are ignored.

cheats = 2

cheat0_desc = "Infinite Health"
cheat0_address = 47154
cheat0_value = 99
cheat0_cheat_type = 1
cheat0_memory_search_size = 3
cheat0_handler = 1
cheat0_enable = true
cheat0_big_endian = false
cheat0_address_bit_position = 0
cheat0_repeat_count = 1
cheat0_repeat_add_to_value = 0
cheat0_repeat_add_to_address = 1
cheat0_code = ""
cheat0_rumble_type = 0
cheat0_rumble_value = 0
cheat0_rumble_port = 0
cheat0_rumble_primary_strength = 0
cheat0_rumble_primary_duration = 0
cheat0_rumble_secondary_strength = 0
cheat0_rumble_secondary_duration = 0

cheat1_desc = "Infinite Lives"
cheat1_address = 65313
cheat1_value = 9
cheat1_cheat_type = 1
cheat1_memory_search_size = 3
cheat1_handler = 1
cheat1_enable = true
... (same fields as cheat0, but with cheat1_ prefix)
Important: The cheats = N line tells RetroArch how many cheats to load (it is parsed in a first pass, so technically it can appear anywhere in the file, but by convention it comes first). Each cheat then uses the prefix cheatN_ where N is the index (starting from 0).

3. Field Reference

Each cheat entry has the following fields. Most are optional — RetroArch uses default values if a field is missing.

FieldTypeDefaultDescription
descstring""Human-readable description shown in the cheat menu
codestring""Emulator-specific code (Game Genie, GameShark, etc.) — used when handler=0
enableboolfalseWhether the cheat is active (enabled) when loaded
big_endianboolfalseByte order for multi-byte values (see Endianness section)
handlerint00 = EMU (emulator code), 1 = RETRO (memory write). If the field is omitted, RetroArch treats the cheat as EMU (0) — always write it explicitly for memory-write cheats.
memory_search_sizeint3Bit width: 0=1-bit, 1=2-bit, 2=4-bit, 3=8-bit, 4=16-bit, 5=32-bit
cheat_typeint1What the cheat does: 1=Set, 2=Inc, 3=Dec, 4-7=Conditional
valueint0The value to write (decimal, not hex!)
addressint0Memory address to write to (decimal, not hex!)
address_bit_positionint0For 1/2/4-bit cheats: which bit(s) to modify (0-7)
repeat_countint1How many times to repeat the write (for multi-address cheats)
repeat_add_to_valueint0Amount added to value on each repeat
repeat_add_to_addressint1Address offset added on each repeat (in memory_search_size blocks)
rumble_*int0Rumble feedback settings (usually left at 0)
Critical: address and value are in DECIMAL, not hex! If a code note says address 0xB832, you must convert it: 0xB832 = 47154 in decimal.

4. Cheat Types Explained

The cheat_type field controls what happens when the cheat is enabled:

ValueNameDescription
0DisabledCheat does nothing
1Set ValueWrites value to address every frame. This is the most common type — it "locks" a value (e.g. infinite health)
2IncreaseAdds value to the current value at address every frame. Use with caution — values increase rapidly!
3DecreaseSubtracts value from the current value every frame
4If EqualConditional: if current value == value, execute the next cheat in the list
5If Not EqualConditional: if current value != value, execute next cheat
6If Less ThanConditional: if value < current value (i.e. current > value), execute next cheat. Note the operand order — see the warning below.
7If Greater ThanConditional: if value > current value (i.e. current < value), execute next cheat. Note the operand order — see the warning below.
When to use each type:
  • Set Value (1): Infinite health, infinite lives, infinite ammo, unlock characters, freeze timer
  • Increase (2): Add points to score (rarely used)
  • Decrease (3): Reduce enemy health (rarely used)
  • Conditionals (4-7): Advanced multi-step cheats. For example: "If boss health < 50, then set boss health to 0" — which, due to the operand order below, is expressed with cheat_type 7 (If Greater Than) and value 50
Operand order of "If Less Than" / "If Greater Than" (RetroArch quirk): RetroArch evaluates these as value < current_value (type 6) and value > current_value (type 7) — the cheat's value is compared against the current memory value, the opposite of what the names suggest. So:
  • type 6 (If Less Than), value=50 → next cheat runs when the current value is greater than 50
  • type 7 (If Greater Than), value=50 → next cheat runs when the current value is less than 50
This matches the upstream implementation of RUN_NEXT_IF_LT / RUN_NEXT_IF_GT and is kept for compatibility. Double-check your conditionals — swapped operands are the most common conditional bug.

For conditionals, the "next cheat" is simply the cheat with the next index. For example, if cheat0 is "If Equal" and its condition is met, cheat1 will be executed. If the condition is NOT met, cheat1 is skipped. The skip applies to exactly one cheat — cheat2 runs normally again. A conditional cheat never writes memory itself; it only gates the cheat after it.

5. Handlers: RETRO vs EMU

RetroArch supports two ways to apply cheats:

RETRO Handler (handler = 1)

This is the most common handler. RetroArch directly reads/writes the core's memory. You specify a memory address and a value to write there.

Most cheats you create from code notes will use this handler. Note: although handler 1 is what you usually want, a .cht entry that omits the handler field entirely loads as EMU (0) — so always write handler = 1 explicitly for memory-write cheats.

EMU Handler (handler = 0)

This uses emulator-specific cheat code formats like Game Genie, GameShark, Pro Action Replay, etc. The code is stored in the code field as a string.

The core's emulator must support the code format for this to work. For Genesis/Mega Drive, Game Genie codes are supported by most cores (like Genesis Plus GX).

Example EMU cheat: 
cheat0_desc = "Infinite fighters for both players"
cheat0_code = "AT4A-AA48"
cheat0_handler = 0
cheat0_enable = true
Note: when using EMU handler, address, value, and memory_search_size are ignored.

6. Memory Search Sizes

The memory_search_size field tells RetroArch how many bits to read/write at the specified address:

ValueSizeRangeUse When
01-bit0-1Boolean flags (on/off, alive/dead)
12-bit0-3Small enumerations
24-bit0-15Nibbles, small counters
38-bit0-255Most common! Health, lives, items, level numbers
416-bit0-65535Score, large counters, pairs of bytes
532-bit0-4294967295Very large values (rare on older consoles)
For 1-bit, 2-bit, and 4-bit sizes: You must also set address_bit_position to specify which bit(s) within the byte to modify. The valid range depends on the size: 1-bit → 0–7 (single bit), 2-bit → 0–3 (bit pairs 00/01/02/03 = 00000011, 00001100, 00110000, 11000000), 4-bit → 0–1 (nibbles 0 = 00001111, 1 = 11110000). For 8-bit and larger, this field is ignored — leave it 0.

7. Endianness

Some consoles store multi-byte values in "big-endian" order (most significant byte first), while others use "little-endian" (least significant byte first).

ConsoleEndiannessSet big_endian to
Sega Genesis/Mega Drive (68000)Big-endiantrue
NESLittle-endianfalse
SNESLittle-endian (usually)false
Game Boy / GBALittle-endianfalse
PlayStationLittle-endianfalse
When does this matter? Only for 16-bit and 32-bit cheats. For 8-bit and smaller, endianness doesn't matter. If your 16-bit cheat doesn't work, try toggling big_endian.

8. Repeat (Multi-Address Cheats)

Sometimes you want to write the same value to multiple consecutive addresses — for example, setting all enemy health values to 0 at once. The repeat fields let you do this with a single cheat entry.

  • repeat_count: How many times to write (default: 1)
  • repeat_add_to_value: How much to add to the value after each write (default: 0)
  • repeat_add_to_address: How many data blocks to skip forward in memory after each write (default: 1)
Example: Setting 7 enemy health addresses to 0, where each enemy's health is stored 128 bytes apart: 
cheat0_desc = "Kill All Enemies"
cheat0_address = 47410        # First enemy's health address
cheat0_value = 0
cheat0_cheat_type = 1
cheat0_memory_search_size = 3  # 8-bit
cheat0_repeat_count = 7        # Write to 7 addresses
cheat0_repeat_add_to_value = 0 # Same value (0) each time
cheat0_repeat_add_to_address = 128 # Skip 128 bytes between enemies

Note: repeat_add_to_address is measured in data blocks, not bytes. For 8-bit (memory_search_size=3), one block = 1 byte. For 16-bit (memory_search_size=4), one block = 2 bytes. For 32-bit (memory_search_size=5), one block = 4 bytes.

9. Using RetroAchievements Code Notes

RetroAchievements maintains "code notes" for many games — these are documented memory addresses discovered by the community. They're the best source for creating cheats.

How to Read Code Notes

A code note looks like this:

0xb832    Player 1's Health

This means:

  • The memory address is 0xB832 (hexadecimal)
  • The value at this address represents Player 1's health
  • To create an "Infinite Health" cheat, you would set this address to a high value (like 99) every frame

Converting Hex to Decimal

Cheat files require decimal addresses and values. You must convert hex to decimal:

Step-by-Step: Creating a Cheat from a Code Note

  1. Find the code note you want (e.g. "0xB832 = Player 1's Health")
  2. Convert the hex address to decimal: 0xB832 = 47154
  3. Decide what value to set (e.g. 99 for near-full health)
  4. Convert the value to decimal if it's in hex (99 decimal = 99, 0x63 = 99)
  5. Determine the data size — health is usually 8-bit (0-255), so memory_search_size = 3
  6. Determine endianness — Genesis is big-endian, so big_endian = true
  7. Create the cheat entry

Result:

10. Using Game Genie / GameShark Codes

Many classic consoles have their own cheat code formats. RetroArch can use these via the EMU handler (handler = 0). The code goes in the code field as a string.

Game Genie (Genesis/Mega Drive)

Genesis Game Genie codes look like XXXX-XXXX (8 characters with a dash). For example:

cheat0_desc = "Infinite fighters for both players"
cheat0_code = "AT4A-AA48"
cheat0_handler = 0
cheat0_enable = true
cheat0_memory_search_size = 0
cheat0_cheat_type = 0
cheat0_address = 0
cheat0_value = 0

GameShark / Pro Action Replay

For other consoles (Game Boy, GBA, N64, PlayStation), the code format differs. GameShark codes typically look like 010138CD (8 hex digits). Pro Action Replay codes are similar. Put them in the code field the same way.

12. Writing .cht Files by Hand

You can create a .cht file from scratch using any text editor (Notepad, VS Code, etc.). Follow these steps:

  1. Create a new text file with a .cht extension (e.g. streets_of_rage.cht)
  2. Add a comment line: # My cheat file
  3. Add the cheat count: cheats = 1
  4. For each cheat, add all required fields with the cheatN_ prefix
  5. Save the file as plain text (UTF-8 encoding)
Minimal cheat template (copy and modify): 
cheats = 1

cheat0_desc = "Your Cheat Description"
cheat0_address = 0          # DECIMAL address (convert from hex!)
cheat0_value = 0            # DECIMAL value (convert from hex!)
cheat0_cheat_type = 1       # 1 = Set Value
cheat0_memory_search_size = 3  # 3 = 8-bit
cheat0_handler = 1          # 1 = RETRO (memory write)
cheat0_enable = true        # true = enabled on load
cheat0_big_endian = false   # true for Genesis, false for NES/SNES/GB
cheat0_address_bit_position = 0
cheat0_repeat_count = 1
cheat0_repeat_add_to_value = 0
cheat0_repeat_add_to_address = 1
cheat0_code = ""

13. Loading Cheats in RetroArch

  1. Copy your .cht file to RetroArch's cheat directory:
    • Windows: C:\Users\YourName\AppData\Roaming\RetroArch\cheats\
    • Android: /storage/emulated/0/RetroArch/cheats/
    • Linux: ~/.config/retroarch/cheats/
  2. Start RetroArch and load your game
  3. Open the Quick Menu (press F1 or the menu button during gameplay)
  4. Select Cheats
  5. Press Load Cheat File (or Load)
  6. Navigate to your .cht file and select it
  7. The cheats will appear in the list — toggle them on/off with the checkboxes
  8. Press Apply Cheat Changes to activate
  9. Return to the game — the cheats are now active!
Tip: If you don't see the cheat file, make sure:
  • The file has a .cht extension
  • The file is in the correct cheats directory
  • The file is plain text (not rich text or Word document)
  • You're using a compatible core (e.g. Genesis Plus GX for Genesis games)

14. Troubleshooting

Cheat doesn't work

  • Check that address and value are in decimal, not hex
  • Verify the address is correct — double-check the hex-to-decimal conversion
  • Try toggling big_endian (especially for 16-bit cheats on Genesis)
  • Make sure cheat_type is 1 (Set Value) for most cheats
  • Ensure handler is 1 (RETRO) for memory-write cheats
  • Check that memory_search_size matches the data type (usually 3 for 8-bit)

Game crashes when cheat is enabled

  • The address might be wrong — writing to the wrong address can crash the game
  • Try a smaller value
  • Disable other cheats to check for conflicts

EMU (Game Genie) code doesn't work

  • Not all cores support Game Genie codes — check the core's documentation
  • Make sure the code is entered correctly (including the dash)
  • For multi-code cheats, separate codes with +
  • Try the equivalent RETRO cheat instead (using the code notes)

Cheat file not showing in RetroArch

  • Verify the file is in the correct cheats directory
  • Make sure the file extension is .cht (not .cht.txt)
  • Check that cheats = N matches the actual number of cheat entries

Values change back immediately

  • This is normal if cheat_type = 1 (Set Value) and the cheat is enabled — RetroArch re-writes the value every frame, which is how "freeze" works
  • If you want a one-time write, disable the cheat after applying it
