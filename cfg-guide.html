1. What is a .cfg file?

A .cfg file is the configuration file used by the RA-BP Quick Cheat system — a custom cheat manager built into the RA-BP fork of RetroArch. Unlike standard RetroArch .cht files (which use a flat key = value format), Quick Cheat uses a compact pipe-separated format organized into sections, allowing a single cheat to write to up to 16 memory addresses at once.

Each .cfg file stores two things in one place: the Quick Cheat popup's window settings, and all the cheat entries for a specific game. The file is auto-saved when you close the popup and auto-loaded when you open it, so you normally never need to edit it by hand — but understanding the format lets you create, share, and fine-tune cheat files directly.

Key points:
  • Files are plain text — open them in any text editor (Notepad, VS Code, etc.)
  • One file per game, organized by core name and ROM name
  • Two sections: [settings] (optional) and [cheats]
  • Cheat entries use pipe | as a field separator — much more compact than .cht
  • Addresses and values are in hexadecimal (no 0x prefix), unlike .cht which uses decimal
  • One cheat can write to up to 16 addresses simultaneously (multi-write)
  • Comments start with #
Quick Cheat vs RetroArch .cht: If you already know the RetroArch .cht format, the main differences are: (1) .cfg uses pipe-separated fields instead of key = value pairs, (2) addresses/values are hex not decimal, (3) one cheat entry can hold multiple writes, (4) hotkeys and groups are built-in, and (5) there is an optional [settings] section for the popup window. Quick Cheat can also import and export standard .cht files for interoperability.

2. File Location & Naming

Quick Cheat stores each game's config in a per-game file. The path is constructed automatically from the RetroArch executable directory, the loaded core name, and the ROM name:

<RetroArch_dir>/quick_cheat_profiles/<core_name>/<rom_name>.cfg

Examples

CoreROMConfig Path
genesis_plus_gx_libretro.dllStreets of Rage (USA).mdquick_cheat_profiles/genesis_plus_gx_libretro/Streets of Rage (USA).cfg
snes9x_libretro.dllSuper Mario World.smcquick_cheat_profiles/snes9x_libretro/Super Mario World.cfg
nestopia_libretro.dllSuper Mario Bros. (JU).nesquick_cheat_profiles/nestopia_libretro/Super Mario Bros. (JU).cfg

How Names Are Derived

  • Core name: The core DLL's filename without its extension. For example, genesis_plus_gx_libretro.dll becomes genesis_plus_gx_libretro.
  • ROM name: The content file's name without its extension. If the ROM is inside a zip (e.g. game.zip#game.nes), the part after # is used. Characters that are illegal in filenames (< > : " / \ | ? *) are replaced with underscores.
  • If the core or ROM name cannot be determined (e.g. no content loaded), the word default is used instead.
Sidecar files: Quick Cheat may also create two files alongside the .cfg:
  • <rom_name>.cfg.bookmarks — saved memory bookmarks (address + size + label)
  • quick_cheat_log.txt — a rotating log (max 1000 lines) in the RetroArch directory, useful for debugging

3. File Structure Overview

A .cfg file has two sections, both optional in principle but conventionally both present:

# RA-BP Quick Cheat Config v2.2
# This file is auto-generated. Do not edit while popup is open.

[settings]
notify=0
auto_apply=0
x=100
y=100
w=900
h=600

[cheats]
# Fields: addr|val|desc|size|type|enabled|freeze|bigendian|group|handler|code|hotkey
# Multi-write: addr/val/size/type/bigendian can be ;-separated.

B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0|0||0|0|0
FF21|09|Infinite Lives (P1)|8|set|1|1|0|Player 1|1||0|0||0|0|0
Section rules:
  • Section headers are lines starting with [ — specifically [settings] and [cheats].
  • Lines starting with # are comments and are ignored.
  • Blank lines are ignored.
  • If a section header is missing, Quick Cheat still tries to parse keys (notify=, x=, etc.) wherever they appear, and treats non-key lines in the cheats area as cheat entries. This makes the format forgiving.

4. The [settings] Section (Optional)

The [settings] section stores the Quick Cheat popup's window position, size, and two behavior toggles. This entire section is optional — if any key is missing, Quick Cheat uses a built-in default. If the section is absent entirely, all defaults are used. This means a .cfg file can contain nothing but a [cheats] section and Quick Cheat will still load it correctly.

Settings Keys

KeyTypeDefaultDescription
notify0 or 10Whether to show on-screen notifications when a hotkey fires a cheat (1 = on, 0 = off)
auto_apply0 or 10Whether to automatically apply all enabled cheats when content loads (1 = on, 0 = off)
xint (pixels)100Popup window left-edge X coordinate
yint (pixels)100Popup window top-edge Y coordinate
wint (pixels)900Popup window width (capped at 65% of screen width)
hint (pixels)600Popup window height (capped at 75% of screen height)
The [settings] section is NOT mandatory. You can omit it entirely. You can also include only some keys — missing keys fall back to their defaults. The parser even recognizes notify=, auto_apply=, x=, y=, w=, h= outside of any section, so a file with no [settings] header but with these keys will still load them. This is by design: the format is forgiving so hand-written files "just work."

Minimal Example (No Settings)

This is a perfectly valid .cfg file — no [settings] section at all:

[cheats]
B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0

Full Example (With Settings)

# RA-BP Quick Cheat Config v2.2

[settings]
notify=1
auto_apply=0
x=120
y=80
w=1000
h=700

[cheats]
B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0

5. The [cheats] Section

The [cheats] section is where the actual cheat entries live. Each non-comment, non-blank line in this section is one cheat entry. Fields are separated by the pipe character |. This is far more compact than the RetroArch .cht format — a single line holds an entire cheat with all its properties.

Basic Single-Write Cheat

B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0

This single line creates a cheat that writes the hex value 50 (decimal 80) to address B832 every frame, with the description "Infinite HP (P1)", in the "Player 1" group, using the RETRO memory-write handler, and no hotkey.

Multi-Write Cheat

B932;B9B5;BA32;BB32;BBB2;BAB2;BCB2|00|Kill All Enemies|8|set|1|0|0|Kill All|1||10

This one line creates a cheat that writes 00 to seven enemy health addresses simultaneously, assigned to the Ctrl+Num1 hotkey (hotkey ID 10). The addresses are separated by semicolons ;.

Why pipe-separated? The pipe format was chosen for compactness. A 12-field cheat that would take 12 lines in .cht format fits on a single line in .cfg. This makes large cheat files (50+ entries) manageable and easy to share in chat or forum posts.

6. Field Reference (All 17 Fields)

Each cheat line has up to 17 pipe-separated fields. The first 12 are the "core" fields (v2.0). Fields 13–14 were added in v2.8, and fields 15–17 in v3.0. Fields 13–17 are optional — if they are missing or empty, sensible defaults are used. This means old v2.0 cheat files still load perfectly in v3.6.

#FieldTypeDefaultDescription
1addrhex—Memory address (no 0x prefix). Multi-write: ;-separated list, up to 16 addresses.
2valhex0Value to write (no 0x prefix). Single value broadcasts to all writes. Multi-write: ;-separated.
3descstring""Description shown in the cheat list (escaped — see Escape Rules).
4sizeint8Bit width: 8, 16, or 32. Multi-write: ;-separated.
5typestringsetCheat type: set, inc, dec, eq, neq, lt, gt. Multi-write: ;-separated.
6enabled0/111 = cheat is active (will apply). 0 = disabled (does nothing).
7freeze0/101 = re-apply every frame ("freeze" the value). 0 = one-shot only. Ignored for conditional types (eq/neq/lt/gt).
8bigendian0/101 = big-endian byte order (Sega Genesis/68000). 0 = little-endian (NES, SNES, GB, PSX). Multi-write: ;-separated.
9groupstring""Logical grouping shown in the filter dropdown (escaped). E.g. "Player 1", "Enemies", "Hotkeys".
10handlerint00 = EMU (Game Genie/GameShark code string). 1 = RETRO (direct memory write). Most cheats use 1.
11codestring""Emulator code string, only used when handler=0 (escaped). E.g. AT4A-AA48.
12hotkeyint00 = none. 1–9 = Numpad 1–9. 10–18 = Ctrl+Num 1–9. 19–27 = Alt+Num 1–9.
13timingint0(v2.8, optional) Apply every N frames. 0 or 1 = every frame. 2 = every 2nd frame, etc. Slows down freeze rate.
14notesstring""(v2.8, optional) Per-cheat notes for your own reference (escaped). Not shown in the list, but visible in the edit dialog.
15range_lock0/10(v3.0, optional) 1 = enable value range lock. When on, Quick Cheat reads the current value and clamps it to [range_min, range_max] instead of writing a fixed value.
16range_minhex0(v3.0, optional) Minimum allowed value (hex, no prefix). Only used when range_lock=1.
17range_maxhex0(v3.0, optional) Maximum allowed value (hex, no prefix). Only used when range_lock=1.
Critical difference from .cht: In Quick Cheat .cfg files, addresses and values are written in hexadecimal without the 0x prefix (e.g. B832, not 47154). In RetroArch .cht files, the same address is written in decimal as 47154. Always double-check which format you are editing!
Optional trailing fields: Fields 13–17 can be omitted entirely. A cheat line with only 12 fields is perfectly valid and will load with timing=0, empty notes, and range_lock=0. This preserves backwards compatibility with v2.0 cheat files.

7. Cheat Types

The type field (field 5) controls what happens when the cheat is applied. There are seven types: three "action" types and four "conditional" types.

KeywordIDNameDescription
set1Set ValueWrites val to addr. This is the most common type — use it for infinite health, infinite lives, unlocking characters, freezing timers, etc.
inc2IncreaseAdds val to the current value at addr. For hotkey cheats, val is the amount added per press.
dec3DecreaseSubtracts val from the current value. For hotkey cheats, val is the amount subtracted per press.
eq4If EqualConditional: if the current value at addr equals val, execute the next cheat in the list. Otherwise skip it.
neq5If Not EqualConditional: if current value ≠ val, execute the next cheat. Otherwise skip it.
lt6If Less ThanConditional: if current value < val, execute the next cheat.
gt7If Greater ThanConditional: if current value > val, execute the next cheat.
When to use each:
  • set — Infinite health, infinite lives, infinite ammo, unlock characters, freeze timer, stage select, difficulty change
  • inc / dec — Hotkey-triggered adjustments: "HP +10", "Score +10000", "Lives -1". Also useful for one-shot score boosts.
  • eq / neq / lt / gt — Multi-step conditional cheats. For example: cheat N checks "if boss health < 50" and cheat N+1 (which runs only if the condition is met) sets boss health to 0.
Conditionals and freeze: If any write in a cheat uses a conditional type (eq/neq/lt/gt), the freeze flag is automatically forced to 0. Conditionals are evaluated per-application, not per-frame — they gate whether the next cheat runs.

8. Memory Sizes

The size field (field 4) tells Quick Cheat how many bits to read or write at the address. Unlike RetroArch's .cht format (which uses codes 0–5), Quick Cheat uses the actual bit count for clarity.

ValueSizeRangeUse When
88-bit (1 byte)0–255 (0–FF)Most common. Health, lives, items, level numbers, character IDs, flags
1616-bit (2 bytes)0–65535 (0–FFFF)Scores, large counters, 16-bit timers, pair-of-bytes values
3232-bit (4 bytes)0–4294967295Very large values (rare on 8/16-bit consoles; more common on PSX/N64)
Endianness matters for 16-bit and 32-bit. For 8-bit writes, the bigendian field is ignored. For 16/32-bit, you must set bigendian correctly or your cheat will write to the wrong bytes. See the next section.

9. Endianness

Multi-byte values can be stored in memory in two orders. "Big-endian" stores the most significant byte first (lowest address). "Little-endian" stores the least significant byte first. If you get this wrong on a 16-bit or 32-bit cheat, the value will be garbled or written to the wrong half of the pair.

ConsoleEndiannessbigendian field
Sega Genesis / Mega Drive (68000)Big-endian1
Arcade (varies by board)Often big-endian1 (try first)
NESLittle-endian0
SNESLittle-endian0
Game Boy / GBC / GBALittle-endian0
PlayStation / PS2Little-endian0
Nintendo 64Big-endian1
Rule of thumb: If your 8-bit cheat works but your 16-bit cheat produces weird results, toggle bigendian. For 8-bit cheats, this field does nothing. For multi-write cheats, bigendian can be ;-separated if different writes need different byte orders (rare).

10. Multi-Write Cheats

One of Quick Cheat's signature features is multi-write: a single cheat entry can write to up to 16 different memory addresses in one operation. This is perfect for "kill all enemies" (write 0 to 7 enemy health addresses), "max all stats" (write max to strength, speed, defense, etc.), or "clear all stage flags" simultaneously.

How It Works

Fields that support multi-write use semicolons ; to separate per-write values:

  • addr (field 1): B932;B9B5;BA32 = three addresses
  • val (field 2): 00;01;02 = three different values, one per address
  • size (field 4): 8;8;16 = per-write sizes (usually all the same)
  • type (field 5): set;set;set = per-write types (usually all the same)
  • bigendian (field 8): 0;0;1 = per-write endianness (usually all the same)

Value Broadcasting

If val has only one value but addr has multiple, that single value is broadcast to all writes. Same for size, type, and bigendian. This means you usually only need to specify one value even for multi-write cheats.

addr fieldval fieldResult
B932;B9B5;BA3200Write 00 to all three addresses (broadcast)
B932;B9B5;BA3200;01;02Write 00 to B932, 01 to B9B5, 02 to BA32 (per-write)
FA78;FF0601;04Write 01 to FA78, 04 to FF06 (per-write, two different values)

Examples

Kill All Enemies (broadcast value)

B932;B9B5;BA32;BB32;BBB2;BAB2;BCB2|00|Kill All Enemies|8|set|1|0|0|Kill All|1||10

Seven enemy health addresses, all set to 00. The single 00 in the val field broadcasts to all seven writes. Hotkey 10 = Ctrl+Num1.

Clear Stage (per-write values)

FA78;FF06|01;04|Clear Stage|8|set|1|0|0|Clear Stage|1||11

Two addresses with two different values: FA78 ← 01 (boss complete flag) and FF06 ← 04 (level complete flag). Hotkey 11 = Ctrl+Num2.

Limit: A single cheat can have at most 16 writes (16 addresses). If you need more, split into multiple cheat entries. The total cheat list can hold up to 256 entries.

11. Hotkeys

Quick Cheat supports 27 hotkey slots, all based on the numeric keypad (Numpad). The hotkey field (field 12) encodes which slot a cheat is assigned to. When you press the corresponding key combination during gameplay, the cheat is applied as a one-shot (regardless of its freeze setting).

IDKey CombinationNotes
0(none)No hotkey — the cheat is only applied via the Apply button or freeze loop
1–9Numpad 1 – Numpad 9Single-key, no modifier
10–18Ctrl + Numpad 1 – Ctrl + Numpad 9Two-combo
19–27Alt + Numpad 1 – Alt + Numpad 9Two-combo

Special Hotkeys (Not Cheat Slots)

These are built-in and cannot be assigned to cheats:

KeyAction
Numpad 0Open / close the Quick Cheat popup
Ctrl + Numpad 0Apply all enabled cheats (one-shot)
Alt + Numpad 0Disable all cheats
Hotkey behavior: When a hotkey fires, Quick Cheat applies all enabled cheats that share that hotkey ID, as a one-shot. This means you can group several cheats under one hotkey to fire them together (e.g. "HP +10" and "Special +1" both on Num3). The freeze flag is irrelevant for hotkey application — freeze only affects the per-frame loop.

Hotkey Examples

# Num1: HP +10 (P1)
B832|0A|HP +10 (P1) [Num1]|8|inc|1|0|0|Hotkeys|1||1

# Num2: HP -10 (P1)
B832|0A|HP -10 (P1) [Num2]|8|dec|1|0|0|Hotkeys|1||2

# Ctrl+Num1: Kill All Enemies (7 addresses at once)
B932;B9B5;BA32;BB32;BBB2;BAB2;BCB2|00|Kill All Enemies [Ctrl+1]|8|set|1|0|0|Kill All|1||10

12. Escape Rules

Because the pipe | separates fields and newlines separate cheat entries, special characters in text fields (desc, group, code, notes) must be escaped. Quick Cheat uses backslash escapes:

CharacterEscape SequenceWhy
| (pipe)\pPipe is the field separator — an unescaped pipe would split the field
\n (newline)\nNewline would start a new cheat line
\r (carriage return)\rPart of Windows line endings
\ (backslash)\\Backslash itself must be escaped so \p etc. are unambiguous
Example: A description like Health | Ammo (P1\nP2) would be stored as: 
Health \p Ammo (P1\nP2)
When Quick Cheat reads this back, it converts \p back to | and \n back to a newline.
When to worry about escaping: Most cheat descriptions are plain text ("Infinite Health", "Stage 3") and need no escaping. You only need it if your description contains a pipe, newline, or backslash. Game Genie / GameShark codes never contain these characters, so the code field usually needs no escaping either.

13. Timing & Notes (v2.8)

Version 2.8 added two optional fields that let you fine-tune cheat behavior and document your cheats.

Timing Interval (field 13)

The timing field controls how often a freeze cheat re-applies its value. By default (0 or 1), a freeze cheat writes every frame — 60 times per second on most cores. Setting timing to a higher value slows this down:

timing valueBehavior
0 or 1Apply every frame (default — standard freeze)
2Apply every 2nd frame (30 times/sec)
6Apply every 6th frame (10 times/sec)
60Apply once per second
Use case: Some games detect "too-fast" writes and flag them as cheating, or the value flickers annoyingly when written every frame. A timing of 2–6 often fixes this while still keeping the value locked. This field only affects freeze cheats — one-shot and hotkey cheats ignore it.

Per-Cheat Notes (field 14)

The notes field is a free-form text field for your own reference. It is not displayed in the cheat list, but it is visible in the edit dialog and preserved across saves. Use it to record where you found the address, what the value means, or any caveats:

B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0|0|Found on RetroAchievements. 50 hex = 80 decimal.|0|0|0

14. Value Range Lock (v3.0)

Version 3.0 introduced Value Range Lock, a different way to "freeze" a value. Instead of writing a fixed value every frame, a range-locked cheat reads the current value and only writes if it falls outside the allowed range. This lets the game modify the value freely within bounds, while preventing it from going too low (e.g. death) or too high (e.g. overflow).

The Three Fields

#FieldTypeDescription
15range_lock0/11 = enable range lock. When enabled, the val field is ignored for freeze writes; instead the current value is clamped.
16range_minhexMinimum allowed value. If current < min, write min.
17range_maxhexMaximum allowed value. If current > max, write max.

How It Works

When a freeze cheat has range_lock=1, every frame Quick Cheat does this:

  1. Read the current value at addr
  2. If current < range_min: write range_min
  3. If current > range_max: write range_max
  4. If current is within range: do nothing (let the game's value stand)

Example: Keep HP between 50 and 99

B832|00|HP Lock 50-99 (P1)|8|set|1|1|0|Player 1|1||0|0||1|32|63

This locks Player 1's health so it can never drop below hex 32 (decimal 50) or exceed hex 63 (decimal 99). The game can heal or damage within that range, but the value is clamped at the boundaries. Note: the val field (00) is ignored when range_lock is on, but must still be present as a placeholder.

Range lock vs freeze: A normal freeze (freeze=1, range_lock=0) pins the value to exactly val every frame — the game cannot change it at all. A range lock (freeze=1, range_lock=1) lets the game change the value within [min, max] and only intervenes at the boundaries. Use freeze when you want a fixed value; use range lock when you want a "safety net."

15. Handlers: RETRO vs EMU

The handler field (field 10) selects how the cheat is applied. There are two handlers:

RETRO Handler (handler = 1)

This is the default and most common. Quick Cheat directly reads and writes the core's memory using the addr, val, size, and bigendian fields. This is what you will use for 99% of cheats created from RetroAchievements code notes. The code field is ignored (leave it empty).

EMU Handler (handler = 0)

This handler is for emulator-specific cheat code strings — Game Genie (Genesis), GameShark (GB/GBA/N64), Pro Action Replay (SNES), etc. The code goes in the code field as a string. The addr, val, size, and bigendian fields are ignored for EMU cheats — you still need to include them as placeholders, but their values don't matter.

Behind the scenes, EMU cheats are registered in RetroArch's own cheat manager and applied via the core's cheat code processor. This is the only way Game Genie / GameShark codes work, because they use emulator-specific encoding that the core must decode.

EMU Cheat Example (Game Genie for Genesis)

0000|00|Infinite Fighters (Game Genie)|8|set|1|0|0|Game Genie|0|AT4A-AA48|0

Note: handler=0, the code AT4A-AA48 is in the code field, and the addr/val/size fields are placeholders. Multi-code Game Genie cheats use + to join codes:

0000|00|Start Timer at 99|8|set|1|0|0|Game Genie|0|RGMA-C6VC+XGMA-DA3E|0
Important: Not all cores support EMU cheat codes. If your Game Genie code doesn't work, check the core's documentation. Genesis Plus GX supports Game Genie codes for Genesis games. For other systems, you may need to find the equivalent RETRO cheat (using code notes) instead.

17. Bookmarks File (.bookmarks)

Alongside each .cfg file, Quick Cheat may create a .bookmarks sidecar file. This file stores saved memory addresses for quick access in the Memory Tools tab. The format is simple:

# Quick Cheat Bookmarks
B832|3|Player 1 Health
FF21|3|Player 1 Lives
FF08|4|Score High
FB00|16|Stage Time

Bookmark Fields

#FieldTypeDescription
1addresshexMemory address (hex, no 0x prefix)
2sizeint8, 16, or 32 (same encoding as cheats)
3labelstringFree-form label for the bookmark (not escaped — no pipes allowed)
Automatic management: Bookmarks are saved and loaded automatically with the config file. You normally create them via the Bookmark button in the Memory Tools tab. The maximum is 32 bookmarks per game. You can edit the .bookmarks file by hand, but close the Quick Cheat popup first to avoid your changes being overwritten.

18. Writing .cfg Files by Hand

You can create a .cfg file from scratch using any text editor. Here's the step-by-step process:

  1. Close the Quick Cheat popup if it is open — Quick Cheat auto-saves on close and would overwrite your edits.
  2. Find the correct path: <RetroArch_dir>/quick_cheat_profiles/<core_name>/<rom_name>.cfg. Create the directories if they don't exist.
  3. Create a new text file with the .cfg extension at that path.
  4. Add a header comment: # RA-BP Quick Cheat Config v2.2
  5. (Optional) Add a [settings] section with window preferences. You can skip this entirely if you want.
  6. Add a [cheats] section header.
  7. Add one line per cheat, using the 17-field pipe-separated format.
  8. Save the file as plain text (UTF-8 encoding, no BOM).
  9. Open the Quick Cheat popup (Numpad 0) — your cheats will load automatically.

Minimal Template (Copy & Modify)

# RA-BP Quick Cheat Config v2.2

[cheats]
# addr|val|desc|size|type|enabled|freeze|bigendian|group|handler|code|hotkey
B832|50|Infinite HP|8|set|1|1|0|Player 1|1||0
FF21|09|Infinite Lives|8|set|1|1|0|Player 1|1||0
Only 12 fields are required. Fields 13–17 (timing, notes, range_lock, range_min, range_max) are optional. If you omit them, Quick Cheat uses defaults (timing=0, empty notes, range_lock=0). The minimal format is just the first 12 fields. Old v2.0 cheat files with 12 fields still work perfectly in v3.6.

Converting from RetroArch .cht to .cfg

If you have a .cht file and want to convert it to .cfg format:

  1. Take the decimal address from the .cht and convert to hex (e.g. 47154 → B832).
  2. Take the decimal value and convert to hex (e.g. 99 → 63).
  3. Convert the memory_search_size code to a bit count: 3→8, 4→16, 5→32.
  4. Convert the cheat_type code to a keyword: 1→set, 2→inc, 3→dec, 4→eq, 5→neq, 6→lt, 7→gt.
  5. Convert handler (same numbering: 0=EMU, 1=RETRO).
  6. Convert big_endian true/false to 1/0.
  7. Convert enable true/false to 1/0.
  8. Map freeze to 1 if the cheat is a "Set Value" that should re-apply every frame (in .cht, all enabled cheats freeze; in .cfg you choose).
  9. Assemble: addr|val|desc|size|type|enabled|freeze|bigendian|group|handler|code|hotkey
Tip: Quick Cheat has built-in Import .cht and Export .cht buttons that do this conversion automatically. Use them if you have a large .cht file — no need to convert by hand.

19. Troubleshooting

My .cfg file doesn't load

  • Make sure the file is at the correct path: <RetroArch_dir>/quick_cheat_profiles/<core_name>/<rom_name>.cfg
  • Check that the core name and ROM name match exactly (including capitalization and spacing)
  • Close and reopen the Quick Cheat popup — it only loads the file on open
  • Check quick_cheat_log.txt in the RetroArch directory for error messages
  • Make sure the file is plain text (UTF-8), not a Word document or rich text

Cheat doesn't work

  • Verify the address is correct — in .cfg files, addresses are hex (e.g. B832), not decimal
  • Check the enabled field is 1
  • For freeze cheats, check freeze=1
  • For one-shot cheats, press Apply or the assigned hotkey — they don't apply automatically
  • Try toggling bigendian (especially for 16-bit/32-bit cheats on Genesis)
  • Make sure handler=1 for memory-write cheats (RETRO)
  • Check that size matches the data (8 for most values, 16 for scores, 32 for large)

Game crashes when cheat is enabled

  • The address might be wrong — writing to the wrong address can crash the game
  • Try a smaller value
  • Disable other cheats to check for conflicts
  • If using a freeze cheat on an address the game also writes to, try timing=2 or higher to reduce write frequency

Game Genie / GameShark code doesn't work

  • Make sure handler=0 (EMU) and the code is in the code field
  • Not all cores support EMU codes — check the core's documentation
  • Make sure the code is entered correctly (Game Genie: XXXX-XXXX with a dash)
  • For multi-code cheats, join codes with +: RGMA-C6VC+XGMA-DA3E
  • Try the equivalent RETRO cheat (using code notes) instead

Multi-write cheat only writes to one address

  • Check that addresses are separated by semicolons ; with no spaces: B932;B9B5;BA32
  • If using per-write values, make sure the count matches (or use a single value to broadcast)
  • Maximum is 16 writes per cheat — split into multiple cheats if you need more

Hotkey doesn't fire

  • Make sure enabled=1 — disabled cheats don't fire on hotkey
  • Check the hotkey field is in range 1–27
  • Make sure Num Lock is on (Numpad keys may not register otherwise)
  • Check that no two cheats share the same hotkey unless you want them to fire together
  • Numpad 0, Ctrl+Num0, and Alt+Num0 are reserved — don't use hotkey 0 expecting them to fire a cheat

Value range lock isn't clamping

  • Check range_lock=1 and freeze=1 (range lock only works for freeze cheats)
  • Make sure range_min and range_max are in hex (e.g. 32 for decimal 50)
  • Verify range_min ≤ range_max
  • Range lock reads the first write's address — for multi-write cheats, only write[0] is range-locked

Window position or size is wrong

  • Edit the [settings] section: x, y, w, h
  • Window size is capped at 65% screen width / 75% screen height — very large values are clamped
  • Delete the [settings] section entirely to reset to defaults
