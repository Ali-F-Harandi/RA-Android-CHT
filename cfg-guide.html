1. The RA Cheat System

RA Cheat is the cheat trainer of the RA-BP fork of RetroArch. Unlike the old Quick Cheat popup, it is not built into RetroArch — it is a standalone Python tool (racheat.pyw, standard library only) that connects to RetroArch's built-in Network Command Interface (UDP, default port 55355) and reads/writes the emulated memory from outside the emulator.

This external design has practical advantages. The game keeps running while the trainer is open, so hotkeys and freezes work live (the old popup paused the core). Nothing in the RetroArch main loop depends on the tool, so it can be updated without rebuilding the emulator. And because the protocol is plain UDP, the same tool works against RetroArch running on another device — including RetroArch on Android over WiFi (start it with racheat.pyw --host <phone-ip>).

How it launches

  • Numpad 0 in game: the RA-BP launcher (a ~150-line hook inside the fork) looks for racheat.pyw next to retroarch.exe and starts it. Pressing Num0 again just re-focuses the running instance (single-instance mutex).
  • If the network interface is off: a dialog offers to enable it — network_cmd_enable is switched in memory and written to retroarch.cfg, and the UDP command server starts immediately, no restart needed.
  • Manually: double-click racheat.pyw (needs Python 3.8+ installed) or run racheat.pyw --host <ip> for a remote device.
What RA Cheat does not touch: RetroAchievements. The RA-BP fork disables the hardcore restrictions locally, so achievements keep unlocking while cheats and memory writes are used. The tool only talks to the command interface (plus the public RetroAchievements web API to fetch community code notes).

2. The Two Cheat Types (+2 Handlers)

The system has two kinds of cheats, each stored in its own config file and applied by a different engine. Both live in RA Cheat's window as two tabs: Cheat Table and RetroArch Cheats.

Cheat TableRetroArch Cheats
Tab"Cheat Table""RetroArch Cheats"
Who applies itRA Cheat's own engine writes the values over UDP (WRITE_CORE_RAM / WRITE_CORE_MEMORY)RetroArch's own cheat manager applies them (once per frame), or the core itself
Config filequick_cheat_profiles/<core>/<rom>.cfg (pipe format, this guide)the game's .cht file(s) + <rom>.racheats.json (state)
HandlersRETRO only (RAM writes) — since v1.9both: RETRO (RA writes memory) and EMU (core interprets the code)
Extrasfreeze modes, range lock, timing, hotkeys, groups, multi-writelive add/delete/toggle, multi-file groups, hotkeys, push into the live list

The two handlers (RetroArch concept)

Every RetroArch cheat carries a handler that decides who interprets it:

  • RETRO (handler = 1) — a plain memory write. RetroArch's cheat manager reads the address and writes the value itself, once per frame, for as long as the cheat is enabled. Works with every core.
  • EMU (handler = 0) — an emulator code string (Game Genie, GameShark, Pro Action Replay...). RetroArch hands the string to the core via retro_cheat_set; the core's own cheat engine decodes it. Only some cores implement it, and the code format is console-specific.
Where EMU cheats live since v1.9: the Cheat Table's engine only pokes RAM — it cannot interpret code strings, so an EMU row in the table never did anything. EMU (code) cheats therefore work exclusively through the RetroArch Cheats tab: import them in a .cht file or add them with the Add dialog, keep them enabled in RA's own cheat list. The Cheat Table editor no longer offers a handler choice, and EMU lines in old profiles are skipped on load (with a log note).
Rule of thumb: values you want frozen or adjusted with hotkeys → Cheat Table. Game Genie / GameShark codes and anything RetroArch's own Cheats menu should show → RetroArch Cheats tab (a .cht file).

4. Cheat Table File: Location & Naming

The Cheat Table stores each game's cheats in a per-game .cfg file. The path is built automatically from the folder of racheat.pyw (the RetroArch folder when launched via Numpad-0), the core's system identifier, and the ROM name:

<RetroArch folder>/quick_cheat_profiles/<core>/<rom_name>.cfg

Examples

Core (system id)ROMConfig Path
genesis_plus_gxStreets of Rage (USA).mdquick_cheat_profiles/genesis_plus_gx/Streets of Rage (USA).cfg
snes9xSuper Mario World.smcquick_cheat_profiles/snes9x/Super Mario World.cfg
nestopiaSuper Mario Bros. (JU).nesquick_cheat_profiles/nestopia/Super Mario Bros. (JU).cfg

How Names Are Derived

  • Core folder: the system identifier the core reports over the network interface (e.g. genesis_plus_gx).
  • ROM name: the content file's name without its extension. For a ROM inside a zip (e.g. game.zip#game.nes), the part after # is used. Characters that are illegal in filenames (< > : " / \ | ? *) become underscores.
  • If the core or ROM name cannot be determined (no content loaded), the word default is used.
Old Quick Cheat profiles keep working: if the exact <core>/<rom>.cfg file does not exist but a profile for the same ROM exists under a different core folder (the old popup named folders after the core DLL, e.g. genesis_plus_gx_libretro), that file is picked up automatically — existing cheat collections survive the switch to RA Cheat untouched.

5. .cfg File Structure

A .cfg file has two sections, both optional in principle but conventionally both present:

# RA-BP Quick Cheat Config v2.2
# This file is auto-generated. Do not edit while the tool is open.

[settings]
notify=0
auto_apply=0
x=100
y=100
w=900
h=600

[cheats]
# Fields: addr|val|desc|size|type|enabled|freeze|bigendian|group|handler|code|hotkey
#         |timing|notes|rlock|rmin|rmax|fmode|fmin|fmax   (last 8 optional)

B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0|0||0|0|0|fix|0|0
FF21|09|Infinite Lives (P1)|8|set|1|1|0|Player 1|1||0|0||0|0|0|fix|0|0
Section rules:
  • Section headers are lines starting with [ — specifically [settings] and [cheats].
  • Lines starting with # are comments and are ignored. Blank lines are ignored.
  • Settings keys (notify=, auto_apply=, x=, y=, w=, h=) are recognized anywhere outside the [cheats] section — a file without a [settings] header still loads its settings.
  • Cheat lines require the [cheats] header. A cheat line that appears before any [cheats] header is silently skipped. If your cheats are not loading, this is the first thing to check.

6. The [settings] Section

The [settings] section stores the RA Cheat window's position, size, and two behavior toggles. The whole section is optional — missing keys fall back to built-in defaults, so a .cfg containing nothing but a [cheats] section loads perfectly.

Settings Keys

KeyTypeDefaultDescription
notify0 or 11On-screen (OSD) notifications in RetroArch when a hotkey fires a cheat. Default ON.
auto_apply0 or 10Automatically apply all enabled cheats when the game loads (the "auto-apply on game load" checkbox).
x, yint (pixels)-1Window position. -1/absent = the tool opens where it last was (the global geometry from racheat_settings.json applies).
w, hint (pixels)0Window size. 0 = built-in default size.

Minimal Example (No Settings)

[cheats]
B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0

7. The [cheats] Section

Each non-comment, non-blank line in this section is one cheat entry. Fields are separated by the pipe character | — a single line holds an entire cheat with all its properties, which keeps large cheat files manageable and easy to share.

Basic Single-Write Cheat

B832|50|Infinite HP (P1)|8|set|1|1|0|Player 1|1||0

This line creates a cheat that writes the hex value 50 (decimal 80) to address B832 on every freeze tick, with the description "Infinite HP (P1)", in the "Player 1" group, and no hotkey.

Multi-Write Cheat

B932;B9B5;BA32;BB32;BBB2;BAB2;BCB2|00|Kill All Enemies|8|set|1|0|0|Kill All|1||10

This one line creates a cheat that writes 00 to seven enemy health addresses simultaneously, assigned to the Ctrl+Num1 hotkey (hotkey ID 10). Addresses are separated by semicolons ;.

Cheat Table vs RetroArch .cht: the .cfg pipe format is much more compact than .cht's key = value pairs; addresses and values are hex without a 0x prefix (the .cht format uses decimal); one entry can hold up to 16 writes; hotkeys, groups, freeze modes and range lock are built-in. The tool imports and exports standard .cht files in both directions (each write becomes one .cht entry).

8. Field Reference (All 20 Fields)

Each cheat line has up to 20 pipe-separated fields. The first 12 are the "core" fields (v2.0). Fields 13–14 were added in v2.8, 15–17 in v3.0, and 18–20 (freeze mode + guard bounds) with RA Cheat v1.7. Fields 13–20 are optional — if missing or empty, sensible defaults are used, so old Quick Cheat files still load perfectly.

#FieldTypeDefaultDescription
1addrhex—Memory address (no 0x prefix). Multi-write: ;-separated list, up to 16 addresses.
2valhex0Value to write (no 0x prefix). A single value broadcasts to all writes. Multi-write: ;-separated.
3descstring""Description shown in the cheat table (escaped — see Escape Rules).
4sizeint8Bit width: 8, 16, or 32. Multi-write: ;-separated.
5typestringsetCheat type: set, inc, dec, eq, neq, lt, gt. Multi-write: ;-separated.
6enabled0/111 = cheat is active (checkbox in the On column). 0 = disabled (does nothing).
7freeze0/101 = keep re-applying at the freeze rate ("freeze" the value). 0 = one-shot. Ignored for conditional types (eq/neq/lt/gt).
8bigendian0/101 = big-endian byte order (Sega Genesis/68000). 0 = little-endian (NES, SNES, GB, PSX). Multi-write: ;-separated.
9groupstring""Logical grouping shown in the filter dropdown (escaped). E.g. "Player 1", "Enemies", "Hotkeys".
10handlerint10 = EMU, 1 = RETRO. Kept for file compatibility — the Cheat Table only loads RETRO lines since v1.9; EMU lines are skipped with a log note (use the RetroArch Cheats tab for them).
11codestring""Emulator code string, only used when handler=0 (escaped). E.g. AT4A-AA48. Kept for compatibility.
12hotkeyint00 = none. 1–9 = Numpad 1–9. 10–18 = Ctrl+Num 1–9. 19–27 = Alt+Num 1–9.
13timingint0(optional) Apply every N engine ticks. 0 or 1 = every tick. The freeze engine runs 25–500 Hz (default 100 Hz, configurable) — timing 10 at 100 Hz re-writes the value 10 times per second.
14notesstring""(optional) Per-cheat notes for your own reference (escaped). Visible in the edit dialog.
15range_lock0/10(optional) 1 = enable value range lock: the current value is clamped into [range_min, range_max] instead of writing a fixed value.
16range_minhex0(optional) Minimum allowed value (hex, no prefix). Only used when range_lock=1.
17range_maxhex0(optional) Maximum allowed value (hex, no prefix). Only used when range_lock=1.
18fmodestringfix(v1.7, optional) Freeze mode: fix (hold the value), min (keep ≥ fmin), max (keep ≤ fmax), range (keep fmin..fmax). See Freeze Modes.

20fmaxhex0(v1.7, optional) Guard upper bound (hex, no prefix). Used by the max/range modes.
Critical difference from .cht: in .cfg files, addresses and values are written in hexadecimal without the 0x prefix (e.g. B832, not 47154). In RetroArch .cht files the same address is written in decimal as 47154. Always double-check which format you are editing!
Optional trailing fields: fields 13–20 can be omitted entirely. A line with only 12 fields is perfectly valid and loads with timing=0, empty notes, range_lock=0 and fmode=fix. This preserves compatibility with all old Quick Cheat files.

9. Cheat Types

The type field (field 5) controls what happens when the cheat is applied. There are seven types: three "action" types and four "conditional" types.

KeywordIDNameDescription
set1Set ValueWrites val to addr. The most common type — infinite health, infinite lives, unlocking characters, freezing timers.
inc2IncreaseAdds val to the current value at addr. For hotkey cheats, val is the amount added per press.
dec3DecreaseSubtracts val from the current value. For hotkey cheats, val is the amount subtracted per press.
eq4If EqualConditional (no write itself): if the current value at addr equals val, the next write in the same cheat runs; otherwise it is skipped.
neq5If Not EqualConditional: if current value ≠ val, run the next write in the same cheat.
lt6If Less ThanConditional: if val < current value, run the next write. Note the operand order (RetroArch semantics — see below).
gt7If Greater ThanConditional: if val > current value, run the next write. Note the operand order (RetroArch semantics — see below).
Conditionals gate the next WRITE in the same cheat — not the next cheat entry. A failed condition skips exactly the write that follows the conditional (per-write type lists make this possible), and the gate resets after that. A conditional write never modifies memory itself. Also: if any write in a cheat is conditional, the freeze flag is forced to 0 — conditionals are evaluated when the cheat is applied (Apply button, hotkey), never in the freeze loop.
Operand order of lt / gt (RetroArch quirk): lt means "run the next write if val is less than the current value" (current > val), and gt means "run the next write if val is greater than the current value" (current < val). This matches RetroArch's RUN_NEXT_IF_LT / RUN_NEXT_IF_GT exactly. To express "if boss HP < 50", use gt with val = 32 hex.

Conditional Example: "If boss HP < 50, kill it"

# write 1: gt 32  -> runs next write only if val(0x32) > current, i.e. boss HP < 50
# write 2: set 00 -> sets boss HP to 0, but only when the condition passed
B932;B932|32;00|If boss HP < 50, kill it|8;8|gt;set|1|0|0|Boss|1||0

10. Memory Sizes

The size field tells the engine how many bits to read or write at the address. Only 8, 16 and 32 are recognized — any other value (or a missing field) is treated as 8-bit.

ValueSizeRangeUse When
88-bit (1 byte)0–255 (0–FF)Most common. Health, lives, items, level numbers, character IDs, flags
1616-bit (2 bytes)0–65535 (0–FFFF)Scores, large counters, 16-bit timers
3232-bit (4 bytes)0–4294967295Very large values, 32-bit counters
Addresses are RetroAchievements addresses by default. The tool reads and writes through READ_CORE_RAM / WRITE_CORE_RAM — the same address space the community code notes use. The raw core memory map (READ_CORE_MEMORY, including save RAM) is available as an alternative "domain" (combobox / --domain map). The two domains number regions differently — pick the one that matches where you found the address.

11. Endianness

For 16/32-bit values, bigendian (field 8) selects the byte order at the target address:

  • 0 (default) — little-endian: NES, SNES, Game Boy, PSX, N64...
  • 1 — big-endian: Sega Genesis / Mega Drive (68000), some arcade boards.

Multi-write cheats can mix endian flags with a ;-separated list (0;1;0).

12. Multi-Write Cheats

A single cheat entry can hold up to 16 writes. Fields 1, 2, 4, 5 and 8 accept ;-separated lists; the counts may differ — the loader pads short lists with their first value, and a single value broadcasts to every address:

B932;B9B5;BA32|00|Clear three enemy slots|8|set|1|0|0|Enemies|1||0
B000;B100;B200|63;32;16|Set HP of three players|8| set|1|0|0|HP|1||0
  • Value broadcasting: B932;B9B5;BA32|00 writes 00 to all three addresses (a single value broadcasts).
  • Per-write values: B000;B100;B200|63;32;16 writes 63, 32, 16 respectively.
  • Short lists pad with the first value: |63;32 on three addresses writes 63, 32, 63.
Why one cheat with many writes? One checkbox in the table toggles the whole group at once, one hotkey fires it, and conditionals can gate individual writes inside the group (see the boss-HP example above).

13. Hotkeys

The hotkey field (field 12) binds a numpad combo to the cheat. The game does not need to be focused — the tool listens globally while it runs.

IDKeyIDKeyIDKey
0(none)10Ctrl+Num119Alt+Num1
1–9Num1–Num911–18Ctrl+Num2–Num920–27Alt+Num2–Num9
  • A hotkey applies the cheat (and toggles its checkbox) — for set cheats with freeze=1 it effectively toggles the freeze on/off.
  • Num0 is reserved: it shows / re-focuses the RA Cheat window itself (the RA-BP launcher hook).
  • The same slot can be shared: a Cheat Table cheat, a live RetroArch cheat and a .cht row can all sit on e.g. Num5 — one press fires all of them.
  • Hotkeys for RetroArch-tab cheats are assigned by right-clicking a row there ("Set Hotkey...") and are stored in <rom>.racheats.json (section 19), not in the .cfg.

15. Timing & Notes

Timing Interval (field 13)

The freeze engine re-applies frozen cheats on its own thread at a configurable rate — 25 to 500 ticks per second, default 100 Hz (combobox in the tool; on Windows the engine uses a 1 ms timer resolution for accurate high rates). The timing field slows an individual cheat down: timing = N re-writes only every Nth engine tick. Use it when a game objects to a value being rewritten at full rate (flickering UI, soft-locks), e.g. slowly regenerating HP instead of hard-freezing it.

Per-Cheat Notes (field 14)

Free-form text for your own reference, visible in the edit dialog. Handy for provenance: which code note the address came from, what the value means, who found it.

16. Value Range Lock

A range-locked cheat does not write a fixed value. Instead, every tick it reads the current value and clamps it into [range_min, range_max] — the game can still move the value around freely inside the window, but cannot push it outside.

The Three Fields

FieldMeaning
range_lock (15)1 = enable the clamp behavior
range_min (16)lower bound (hex)
range_max (17)upper bound (hex)

Example 1: HP regen — +1 per tick, capped at 99

# every tick: value = min(value + 1, 99)  -> recovers but never exceeds 99
B832|01|HP regen (cap 99)|8|inc|1|1|0|Player 1|1||0|0||1|0|63

Example 2: HP drain — -1 per tick, floored at 50

# every tick: value = max(value - 1, 50)  -> hard mode, but never below 50
B832|01|HP drain (floor 50)|8|dec|1|1|0|Player 1|1||0|0||1|32|FFFF

17. Freeze Modes (v1.7)

Fields 18–20 refine what "freeze" means for a cheat. The four modes:

fmodeName in the UIBehavior per freeze tick
fixHold valueThe classic freeze: rewrite val every tick (or every N ticks with timing).
minKeep ≥ minWrite val only when the current value dropped below the guard — otherwise leave it alone. Health that dips but recovers instantly to the floor.
maxKeep ≤ maxWrite val only when the current value rose above the guard. A speed cap that never fights the game while you are under it.
rangeKeep in min–maxThe value may move freely between fmin and fmax; only a value outside the band is written back (to val). Boss HP you can damage, but never kill past the floor / heal past the ceiling.
# HP may fluctuate between 32 (50) and 63 (99); outside values snap back
B832|50|Guarded HP 50..99|8|set|1|1|0|Player 1|1||0|0||0|0|0|range|32|63
Guard modes vs range lock: range lock (fields 15–17) clamps toward the bounds (writes the bound value), which suits regen/drain effects. Freeze guard modes (fields 18–20) write the cheat's own val only when the guard is violated, which suits "keep it in a band" effects. Old lines without fmode load as fix — the classic behavior.

18. Handlers: RETRO vs EMU (where each lives now)

RETRO Handler (handler = 1)

A plain memory write. In the Cheat Table the tool's engine performs it over UDP; in the RetroArch Cheats tab RetroArch's own cheat manager performs it once per frame. Same address space, same semantics, two different appliers — the table gives you freeze modes, timing and multi-write; RA's manager gives you the exact same per-frame behavior as a cheat added in RA's own Cheats menu.

EMU Handler (handler = 0)

An emulator code string (Game Genie, GameShark, Pro Action Replay). It only works when RetroArch's cheat manager hands it to the core (retro_cheat_set) — which is why, since v1.9, the Cheat Table does not load or create EMU entries at all. EMU cheats belong in the RetroArch Cheats tab:

  • import them in a .cht file (the tab auto-locates and loads it), or add them with its Add dialog;
  • they appear in RA's own Cheats menu immediately; toggling them here toggles them in RetroArch;
  • legacy .cfg profiles still load — EMU lines are skipped with a log note instead of becoming dead entries.

EMU Cheat Example (Game Genie for Genesis)

# as a .cfg line (legacy - SKIPPED by the Cheat Table since v1.9):
ATBT-AA4C|0|Infinite continues (GG)|8|set|1|0|0|Cheats|0|ATBT-AA4C|0

# instead, put it in the game's .cht file (RetroArch format):
cheat0_desc = "Infinite continues (GG)"
cheat0_code = "ATBT-AA4C"
cheat0_enable = "false"
cheat0_handler = "0"

19. RetroArch Cheats State (.racheats.json)

The RetroArch Cheats tab shows two things: the cheats currently live in RetroArch's own cheat manager (the "Live in RetroArch" group), and the contents of the game's .cht file(s) — each file as its own collapsible From <name>.cht group. The cheats themselves live in the .cht files (standard RetroArch format, see the .cht guide); RA Cheat stores its own state for that tab in a small JSON side file next to the Cheat Table profile:

<RetroArch folder>/quick_cheat_profiles/<core>/<rom>.racheats.json

Keys

KeyTypeMeaning
chtstringAbsolute path of the primary .cht file (auto-located next to the ROM and in cheats/<core>/; re-located automatically on every game change).
cht_extraarray of stringsPaths of extra .cht files added with "Browse .cht..." — each renders as its own group. Entries that no longer exist are dropped with a log note.
enabledobjectEnable flags of the .cht rows, keyed "<file>:<index>" — file 0 is the primary, the index is the cheatN_ number in the file. Example: {"0:0": true, "0:1": false, "1:0": true}. Bare "<index>" keys from v1.8 files still load (treated as file 0).
hotkeysobjectHotkey assignments of the RA-tab rows, keyed by a stable content identity → hotkey ID (1–27, same numbering as the table). Keys: "L|retro|<addr-hex>|<value-hex>" and "L|emu|<code>" for live cheats, "F<file>|<index>" for .cht rows. Content keys survive RetroArch re-indexing its live list when cheats are deleted.

Full Example

{
  "cht": "C:\\RetroArch\\cheats\\genesis_plus_gx\\Streets of Rage.cht",
  "cht_extra": [
    "C:\\RetroArch\\cheats\\genesis_plus_gx\\Streets of Rage (Rev A).cht"
  ],
  "enabled": {"0:0": true, "0:1": false, "1:0": true},
  "hotkeys": {
    "L|retro|b832|50": 3,
    "F0|1": 5
  }
}
What the state file does not contain: the cheat definitions themselves — descriptions, codes, addresses all come from the .cht files. "Save to .cht" writes the enable flags back into every loaded .cht file; the JSON only remembers which files, which flags and which hotkeys.
Push direction: "Apply Checked" pushes checked .cht entries into RetroArch's live list (duplicate-safe — entries already present are skipped and tagged green). Pushed RETRO entries are then applied by RetroArch itself, once per frame, exactly like a cheat added in RA's own Cheats menu. Live rows can also be toggled (CHEAT_SET), deleted (CHEAT_DEL) or created (Add Cheat / CHEAT_ADD) directly from the tab; a live row's hotkey toggles it inside RetroArch.

21. Creating Cheats with RA Cheat

You normally never write these files by hand — the tool writes them. Three workflows cover everything:

A. Memory Scanner → Cheat Table (find unknown values)

  1. Open RA Cheat (Numpad 0) while the game runs.
  2. Scanner tab: pick the value type (byte..float) and "First Scan" with the current value — or unknown initial value, then "Next Scan" with increased / decreased / changed / unchanged after you change the value in game.
  3. Repeat Next Scans until a few candidates remain; double-click one to add it to the Cheat Table (pre-filled).
  4. Tick its checkbox, give it a description, maybe freeze + a hotkey. The .cfg file is written automatically.

B. Community Code Notes → Cheat Table (known addresses)

  1. Code Notes tab: "Auto Detect" (or log in once with your RA account and let "Follow Now Playing" find the game).
  2. The table lists every community-documented address with a live Value column, polled once per second.
  3. Quick Set (v1.9.1): each row has a Set box next to the value — type a byte (0-255, 0xFF or FF) and press Set (or Enter) to write it immediately for quick experiments, without creating any cheat entry.
  4. Double-click a note to open the cheat editor pre-filled with that address and its current value → OK adds it to the Cheat Table.

C. .cht files / Game Genie → RetroArch Cheats tab

  1. Put cheats in a standard .cht file (hand-written or made with the RA CHT Editor) and drop it next to the ROM or in cheats/<core>/ — the tab auto-loads it; "Browse .cht..." adds more files, each as its own group.
  2. Tick the entries you want and press Apply Checked — they are pushed into RetroArch's live list and applied by RA itself (RETRO once per frame; EMU by the core).
  3. Or use Add Cheat in the tab to create a live RETRO write or an EMU code cheat directly.
  4. Right-click → Set Hotkey to toggle any of them from the game with Num / Ctrl+Num / Alt+Num.
Moving cheats between the two types: right-click a live RA cheat → "Copy to Cheat Table" (RETRO writes only — EMU rows are skipped with an explanation). The Cheat Table's "Export .cht" converts table entries into a standard .cht file the RetroArch Cheats tab (or any RetroArch) can load.

23. Writing Config Files by Hand

  1. Open a plain-text editor (Notepad, VS Code) — save as UTF-8 without BOM.
  2. Create the folder quick_cheat_profiles/<core>/ if needed and name the file exactly like the ROM (extension replaced by .cfg).
  3. Start with [cheats] on its own line (cheat lines before it are skipped!), then one line per cheat.
  4. Addresses and values in hex without 0x; sizes are bit counts (8/16/32); types are the keyword tokens (set, inc...).
  5. Close RA Cheat before saving — it auto-saves and would overwrite your edits otherwise.

24. Troubleshooting

Tool cannot connect / "not connected"

  • network_cmd_enable is off in retroarch.cfg — the Numpad-0 launcher offers to flip it (no restart needed), or add the lines manually: 
    network_cmd_enable = "true"
network_cmd_port = "55355"
  • Wrong host: for RetroArch on another device (Android), start with racheat.pyw --host <ip> once — the address is remembered.
  • Windows Firewall blocking Python — allow pythonw.exe on private networks.

Cheats in my .cfg are not loading

  • Missing [cheats] header before the cheat lines (lines before it are skipped).
  • Wrong folder or file name — the core folder must be the system id and the file name must match the ROM name exactly (extension swapped for .cfg).
  • All-EMU file: since v1.9 the Cheat Table skips EMU lines on load — the log notes them; use the RetroArch Cheats tab.
  • Field count below 12, or the address field is not valid hex.

A cheat does nothing

  • Checkbox off in the On column, or "Apply All" not pressed after editing (edits reach the engine instantly; Apply runs the one-shot writes).
  • Freeze cheat with timing so high it almost never fires.
  • EMU/code cheat sitting in the Cheat Table (legacy line) — move it to a .cht file.
  • Wrong domain: an address found in the raw memory map (map) will not read in the RetroAchievements space (rc) and vice versa.
  • Wrong endianness for 16/32-bit values (Genesis = big-endian).

Value flickers / game misbehaves while frozen

  • Raise timing (apply every N ticks) or lower the global freeze rate (25–100 Hz is usually plenty).
  • Switch the cheat's freeze mode from fix to a guard (min/max/range) so the game can breathe inside the bounds.

Multi-file .cht groups, hotkeys or enable flags were forgotten

  • They live in <rom>.racheats.json next to the profile — check the file exists and is valid JSON; a broken file is ignored (defaults apply).
